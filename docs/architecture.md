# 架构

```
条款 PDF / 扫描件
   │  ingest/router.py   按页分流
   ├─ 原生页 ──── native_pdf.py   pdfplumber 取行 + DeepDoc 版面模型
   │               └─ 无边框表格 ─ table.py   MinerU；未安装时用 DeepDoc TSR
   └─ 扫描页 ──── scanned.py      OpenCV 去噪、纠偏 → PaddleOCR；未安装时用 DeepDoc OCR
   ▼
structure/   OCR 纠错 → 标题层级分类（XGBoost）→ 章节树
chunking/    结构感知切分（≤480 token），列表 / 但书合并，句子边界重叠
   ▼
index/       Milvus（HNSW 向量）+ BM25（Elasticsearch，连不上时用 Milvus 内置 BM25）
   ▼
问题 ─ conversation/  话题判断 → 轻量模型改写成独立问句 → 滑窗 + 摘要记忆
     ─ cache/         归一化问句 + 知识库版本 → Redis
     ─ retrieval/     向量 Top-50 ∥ BM25 Top-50 → RRF → 精排 Top-20 → 证据 Top-5
     ─ answer/        拒答预检 → 流式生成 → 引用编号校验 → 无有效引用则拒答
   ▼
api/   FastAPI + SSE  →  frontend/
```

## 解析（`backend/src/clausetrail/ingest/`）

- **分流**：每页先判断是不是扫描页（字符少于 30 个，或图片覆盖 80% 以上）。原生页取 pdfplumber 的行和字号、粗体、缩进，再用 DeepDoc 版面模型给每行标上 text / title / table / header / footer。置信度低于 0.5 的区域不采用。
- **三栏排版**：有的条款是「条号 | 标题 | 正文」三栏，pdfplumber 会把三栏拼成一行。这里按栏间距（大于 0.9 个字号）拆开，标题折到下一行的几个字再接回标题。
- **表格**：有框线的表格用 pdfplumber 取单元格；版面模型认出的无框线表格交给 MinerU，没有安装 MinerU 时用 DeepDoc TSR 识别行、列和合并单元格。版面模型偶尔会把「条号 | 正文」两栏整块判成表格，含条款编号的区域按正文处理。
- **脚注角标**：和正文在同一行、字号不到正文 60%、跟在汉字或中文标点后面的数字和符号（如「不可逆53性」里的 53）不进入正文，但保留它的位置，避免留下空格。跟在字母、数字或右括号后面的上下标（如 T₁N₀M₀、10⁹/L）是公式的一部分，照常保留；例外是编号正好出现在本页脚注区里（如「ICD-10」后面的脚注 24），仍按角标处理。正文和表格用同一套判断。

## 结构（`structure/`）

- **OCR 纠错**：只处理 OCR 来源、置信度低于 0.92 的块。按术语词典和形近字表（如「赔 / 陪」「险 / 检」）纠正。
- **标题层级**：22 个特征，包括相对字号、粗体、缩进、行宽、是否顶到右边界、句末标点、冒号结尾、公式符号、版面标签、上下间距和 8 种编号样式。XGBoost 分成正文 / 章 / 条 / 款 4 类，训练脚本是 `scripts/train_heading_xgb.py`。运行期不加载 libxgboost，而是用 `tree_ensemble.py` 以纯 numpy 执行导出的树：xgboost 和 milvus-lite（faiss）各带一份 libomp，同一进程里同时加载会崩溃。保存模型前会和 XGBoost 的输出对拍，最大误差约 1e-7。
- **章节树**：各家条款的编号体系不同。平安的「1.」挂在「1.6」下面，国寿的「1.」是章。所以层级按编号样式出现的先后决定：栈上已有的样式回到同级，新样式挂到当前标题下。

## 切分（`chunking/`）

- 按章节树递归切分：整节不超过 480 token 就不再往下分，超过了再往下一层。超长段落按句切，超长表格按行切。
- 合并规则：以冒号结尾的引导句和后面的列表条目合并（责任免除清单不会被拆开）；「但…除外」这类但书和前一句合并；相邻段落向量相似度 ≥0.82 时合并。
- 相邻片段之间重叠 1 句，为此预留 80 token：节内的段落按约 400 token 打包成片段，整节超过约 400 token 时在段落之间分开。单个段落、「引导句 + 列表」只要不超过 480 token 就不会被拆开，放不下重叠句时就不加。目录页不入库，表格不参与目录判断。
- 每个片段带溯源元数据：文档、章节路径、起止页、字符偏移、版面框、解析器。

## 检索与回答

- **词典**：jieba 加 571 条保险术语。建索引时预分词；查询时去停用词，并把别名展开成标准术语（如「观察期→等待期」）。
- **召回**：向量和 BM25 并行各取 Top-50，在应用层做 RRF（k=60）融合，取前 20 条精排，最后 5 条作为证据。只用 SQLite 文档记录当前指向的那个版本的片段，先过滤再取前 20 条：重新入库时新旧版本会短暂并存，不过滤的话同一条款会出现两次，旧片段还会占掉精排名额。
- **拒答**：两道检查。生成前，没有召回结果或精排最高分低于阈值（在开发集上标定）时直接拒答。生成时，流式过滤掉不存在的引用编号（处理跨分片的 `[n]` 和全角括号）；回答里没有一个有效引用时，按「无法对应到原文」拒答，已经流出的文字随之撤回。引用写成 `[1,3]`、`【2】` 时统一成 `[1][3]`、`[2]`。
- **缓存**：key 由归一化问句（繁简转换、全半角、别名替换、去语气词）、知识库版本号和回答模型组成。入库或删除文档时版本号加一，旧缓存自然失效。
- **多轮**：先判断话题是否延续（指代词、省略句式、短句规则，加上与上一问的向量相似度）。延续时用轻量模型改写成独立问句；切换时直接用原问题。历史保留最近 4 轮，更早的压缩成 300 字以内的摘要。

## 模型后端（`models/`）

每个组件都有三种实现：阿里云 API（默认）、本地 FlagEmbedding、离线示例实现（不调用外部服务，用于测试和演示）。

| 组件 | 默认 | 接口 |
| --- | --- | --- |
| 向量 | bge-m3 @ PAI-EAS | OpenAI 兼容 `POST /v1/embeddings` |
| 精排 | `ops-bge-reranker-larger` @ OpenSearch | `POST /v3/openapi/workspaces/{ws}/ranker/{id}`，query + doc ≤512 token，超出截断 |
| 改写 / 回答 | Qwen @ 百炼 | OpenAI 兼容 `/compatible-mode/v1` |

## 存储

| 内容 | 位置 |
| --- | --- |
| 向量 + BM25 | Milvus Lite 本地文件 `data/milvus.db`，或 Milvus standalone |
| BM25（默认） | Elasticsearch，whitespace 分词 + `synonym_graph` 同义词 |
| 文档、会话、消息、知识库版本 | SQLite `data/clausetrail.sqlite3` |
| 查询缓存 | Redis；没有配置时用进程内 LRU |
