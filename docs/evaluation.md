# 评测

```bash
python -m eval.gen.synthesize      # 生成评测集（已提交到 eval/datasets/，一般不用重跑）
make ingest                        # 评测读取的是线上同一个索引
make eval                          # 标定 → 检索 → 改写 → 引用 → 切分，报告写到 eval/reports/（本地生成，不提交到仓库）
```

## 数据集（`eval/datasets/`）

| 文件 | 用途 | 构成 |
| --- | --- | --- |
| `dev.jsonl` | 标定 RRF k、拒答阈值 τ | 普通问题、术语问题，以及无关问题（菜谱、天气、样例以外的险种等） |
| `retrieval_test.jsonl` | MRR@10、Recall@5/10 | 普通问题（章节题、细节题、责任免除题）+ 术语定义题（部分用别名问） |
| `rewrite_test.jsonl` | 改写准确率 | 承接 / 话题切换 / 指代 / 省略四类 |
| `citation_sample.jsonl` | 引用准确率 | 从测试集抽样 |
| `parsing_sample_plan.csv` | 解析准确率抽检方案 | 原生 PDF / 扫描件 / 复杂表格，按险种分层 |
| `manifest.json` | 生成参数、各集合条数、文档划分 | — |

每条检索记录的 gold 是条款里的一句原文（附文档、章节路径、页码），不绑定 chunk_id，所以调整切分参数后评测集仍然可用。

### 生成与校验（`eval/gen/`）

1. 用与入库相同的解析和切分流程读取样例条款。
2. **按文档划分**：按文档哈希排序，前 20%（至少 1 份）做开发集，其余做测试集。开发集和测试集不共享文档。
3. 选 gold 句子。**每道题对应一个不同的信息需求，同一句 gold 原文只出一道题，不靠换问法凑数**：
   - 术语定义题（`subtype=definition`）：每个（文档, 标准术语）一道。术语所在章节的标题就是该术语（或其别名）时，取该章节的首句；否则取「术语 + 指 / 是指」开头的定义句。原文写的是别名时用标准术语问；原文写标准术语且有别名时，一半改用别名问，同义词的两个方向都能测到。
   - 章节题（`subtype=section`）：每个章节一道，章节首段的前两句都算 gold。
   - 细节题（`subtype=detail` / `exclusion`）：某个术语在一节里只出现在一句话中时，以「这一节的这个术语」出题，gold 就是这句话；太泛的术语（在一份文档超过四分之一的章节里出现）不用；每节最多 3 道。责任免除章节里的用「涉及 XX 的情况能赔吗」来问。
4. 出题：
   - 默认用模板，不需要密钥（`verified=auto`）。
   - `--mode llm` 时由百炼 Qwen 出题，要求逐字摘抄出处；摘抄不到原文的题目丢弃，再让模型判断「只凭这一句能否回答」（`verified=llm-judge`）。
5. 泄漏检查（`check_leakage.py`），任何一项不通过就不写文件：
   - 开发集和测试集的文档 ID 不相交。
   - gold 句子不重叠。
   - 问题不近似重复（字符 3-gram Jaccard ≥ 0.9）。
   - 各集合内 qid 和问题不重复；同一句 gold 原文不对应多道题。
6. 人工抽检：在 `eval/reports/citation_review.jsonl` 的 `human_ok` 字段里逐条填写 true / false。

## 指标

| 指标 | 定义 |
| --- | --- |
| 命中 | 召回片段与 gold 来自同一份文档，且去掉空白后包含 gold 原句 |
| MRR@10 | 第一个命中片段排名的倒数，前 10 名都没有命中记 0 |
| Recall@k | 前 k 名里是否命中任一句 gold（章节题有两句 gold，其余题一句） |
| 截断率 | 一个语义单元（句子、「引导句 + 条目」列表、短章节）没有完整落在任何一个片段里的比例 |
| 改写准确率 | 承接、指代、省略三类必须改写，且改写结果包含产品简称和追问的术语；话题切换类不应改写 |
| 话题判断准确率 | continue / switch 标签判对的比例 |
| 引用准确率（自动近似） | 作答的问题里，被引用的片段至少有一条包含 gold 原句的比例；回答本身是否正确靠人工抽检 |

## 检索的四种配置

同一条问题只走一遍线上检索（`Retriever.retrieve`），再从中取出各路的排序：

| 配置 | 排序来源 |
| --- | --- |
| 纯向量 | 向量 Top-50 |
| 纯 BM25 | BM25 Top-50（术语别名展开后） |
| 混合（RRF） | 两路做 RRF 融合 |
| 混合 + 精排 | RRF 前 20 条经精排重排 |

## 标定

只在开发集上进行，结果写进 `eval/reports/calibration.json`。测试脚本只读取这个文件，不再调参。

标定结果记录了当时的模型后端；测试脚本发现当前模型和它不一致时不套用，并提示重新标定。线上问答不读这个文件，要让 API 用上标定值，把其中的 `rrf_k`、`refusal_threshold` 写进 `.env` 的 `RRF_K`、`REFUSAL_THRESHOLD`。

- **RRF k**：在 10 / 30 / 60 / 100 中选开发集 MRR@10 最高的，并列时保留默认值 60。
- **拒答阈值 τ**：在可回答问题和无关问题的精排最高分之间扫描，取「该答的答、该拒的拒」平衡准确率最高的阈值，并列时取更小的阈值，减少误拒。

## 报告

`make eval` 把报告写到 `eval/reports/`：

- `summary.md`：汇总。
- `retrieval.md`、`rewrite.md`、`citation.md`、`chunking.md`：各项明细。
- `calibration.json`：开发集上的标定结果。

报告在本地生成，不提交到仓库。报告开头写明文档规模和模型后端；用离线示例模型（`fake` 后端）时，报告会标注「指标仅作示例」。

## 切分评测

- 固定长度基线：每 480 字一段，重叠 50 字。
- 结构感知切分：入库用的同一套规则，上限 480 token。为了在没有向量模型时也能复现，关闭了「相邻段落按向量相似度合并」这一步。
- 两种切分用同一批语义单元计算截断率。只统计不超过 480 token 的列表和章节；目录页不计入。
